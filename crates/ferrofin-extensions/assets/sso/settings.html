Single Sign-On

Let users sign in with an OpenID Connect identity provider, such as Authentik, Authelia, Keycloak or Pocket ID. Changes apply at once.

Public URL

The address users reach this server at, base path included, such as https://media.example.org. Each provider's callback URL is built on it. When it is empty, the Published server URL in Ferrofin Settings is used.

Login page

Adds "Sign in with" and the provider's name under the web client's login form, for each enabled provider, once a public URL is known. The button is added to the login disclaimer the server sends every app, so an app that shows the disclaimer on its own login screen may show the button's text or markup there. Turn this off to remove it for every app; the branding you saved is never changed.

OIDC providers

The claim a user's Ferrofin name is taken from.
A user no account is linked to gets one, named by the username claim, that only signs in through this provider. Off, such a user is refused. A name an account already has is always refused.
After each sign-in, a user's profile picture is set from the image the provider's picture claim names, whenever that image is new or has changed, or the user has no picture, replacing a picture the user set in Ferrofin. It is downloaded under the server's image download limits: a picture on a private address needs that address in the server's image_private_http_allow. A sign-in without the claim, or whose picture cannot be downloaded, leaves the picture as it is; the download never holds up the sign-in. When the ID token has no picture claim, each sign-in also asks the provider's userinfo endpoint for it, which adds one request to the provider, of up to 10 seconds.

Roles

The claim a user's roles or groups are read from, in the ID token or the userinfo answer: a list of names, or one name. A nested claim, such as Keycloak's realm_access.roles, is not read: map the roles or groups to a top-level claim at the provider. Some providers send it only for a scope that asks for it, such as groups: add that scope above. A user whose sign-in carries no such claim has no role.
A user without this role is refused, and no account is created or linked for them. Empty lets every user of the provider sign in. Names are compared exactly.
At each sign-in, a user's administrator flag, libraries and Live TV follow the roles below. Roles are read only at sign-in, so a change at the provider reaches a user at their next sign-in. Off, a sign-in never changes a user's rights.
With role sync on, a user with this role is made an administrator, and a user without it loses the flag, except the last administrator, who keeps it. Empty never changes the flag.

Library and Live TV access

With role sync on, a user's libraries and Live TV access are set from these roles at each sign-in, and nothing else of their access changes. A user with none of these roles gets no library and no Live TV, administrators included. Off, they are not used. One role per line; names are compared exactly.

Linked accounts

A linked identity at a provider signs in to its Ferrofin account. Users link their own account on the page . Removing a link signs out every session of its account. An account that signs in through Single Sign-On only cannot sign in at all without a link, until it is linked again or given another authentication provider on its profile page.

Link an account by hand

The identity's subject at the provider: the sub claim of its ID tokens, which the provider's admin console shows as the user's id. It replaces the account's link at that provider, if it has one. An identity another account has is refused.
